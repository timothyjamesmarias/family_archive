Guidance for Claude Code when working in this repository.

## What This Is

A family archive application for genealogical data and family history, ported
from an AdonisJS app onto the Rails template. Public pages browse artifacts
(photos, letters, documents, ledgers, audio, video) and articles; an
interactive family-tree island renders and edits the genealogy; a
server-rendered admin manages everything.

Stack: Rails 8.1, PostgreSQL, Solid Cache/Queue/Cable, Vite, Tailwind v4,
Turbo + Stimulus, Devise for auth (admin-managed users, no public signup),
Mission Control – Jobs for the queue dashboard.

## Commands

```bash
bin/setup                 # install deps, start Postgres, prepare the database
bin/dev                   # web + vite + jobs
bin/rails test            # unit + integration tests
bin/rails test:system     # system tests (headless Chrome)
npm run typecheck         # tsc --noEmit
npm run test:frontend     # Vitest for the family-tree island
bin/rubocop               # lint
bin/ci                    # everything CI runs
docker compose up -d      # Postgres only (host port 5433)
```

Dev Postgres listens on **5433** (5432 is taken by other local projects).
Seeds create `admin@example.com` / `password` in development.

## Architecture Notes

- **Domain services live in `app/services`**, named after the domain
  (`ArtifactUploader`, `FamilyTree::Mutations`, `IndividualEditor`) — no
  `Service` suffix. Controllers validate, delegate, and shape the response.
- **Recursive CTEs stay as SQL strings** in `app/queries/individual_queries.rb`
  and `app/services/family_tree/metadata.rb`, executed through Active Record.
  They walk parent/child edges to bounded depth; refactor deliberately, with
  the tests in `test/services` as the safety net.
- **Soft deletes** (`SoftDeletable` concern) apply to individuals, families,
  and family_members via a default scope; `with_deleted` escapes it. GEDCOM id
  uniqueness checks must include deleted rows — the DB unique index does.
- **`family_members` has a composite primary key** (family_id, individual_id,
  role) using Rails CPK support.
- **The family-tree island** (`app/frontend/apps/family-tree`) is ported
  verbatim from the AdonisJS app and will eventually be rewritten in React.
  The JSON API under `/api` is a camelCase contract with it — do not rename
  payload keys or paths. `app/frontend/shared/csrf.ts` is the only file that
  changed in the port (reads Rails' meta tag).
- **Artifact files are Active Storage attachments** — `ArtifactFile` has
  `has_one_attached :file` with a preprocessed `:thumb` variant (300px JPEG),
  so thumbnails are generated by `ActiveStorage::TransformJob` on upload.
  The `artifact_files` row carries only `file_sequence` and the annotation
  anchor. Development/test use Disk; production uses S3 (`amazon` service in
  `config/storage.yml`, configured by `AWS_*` env vars).
- **Article HTML is sanitized twice**: `ArticleHtml.sanitize` on save, and the
  `article_html` helper on render.
- **Mission Control** at `/admin/jobs` (admin-gated) shows the Solid Queue
  jobs, including Active Storage's analyze/transform/purge jobs. Development
  uses Solid Queue too (the :async default would keep the dashboard empty), so
  jobs only run under `bin/dev`, which starts the worker. Variant generation
  needs libvips (`brew install vips` locally; the Dockerfile has it).
- **GEDCOM import parses via Node** — Ruby has no maintained GEDCOM parser,
  so `GedcomReader` shells out to `script/gedcom-to-json.mjs` (the same
  `read-gedcom` package the AdonisJS app used) and `GedcomImporter` owns all
  domain logic: upsert by GEDCOM id, replace only BIRTH/DEATH/BAPTISM/BURIAL
  events, preserve hand-added members and events. Imports run through
  `GedcomImportJob`; the admin screen shows the last result from the cache.
  `read-gedcom` is a production npm dependency and the Dockerfile keeps node
  in the runtime image for it.
- **Admin scaffolding**: `bin/rails g admin_scaffold <model> field:type …`
  generates an admin CRUD (controller + views) matching the aside-nav layout;
  add the nav link in `app/views/layouts/admin.html.erb` by hand.

## Frontend

Three Vite entrypoint groups:

- `application.(js|css)` — the admin (Turbo + Stimulus + Tailwind slate).
- `public.(ts|css)` — public pages: dark mode, mobile menu, annotated-photo
  islands; Tailwind with the Paperwhite theme (stone/sage palette, Lora/Inter).
- `family_tree.(ts|css)` — the family-tree island, loaded only on /family-tree.
- `admin_artifact_upload.ts` — the Uppy dashboard on the artifact upload page
  (multi-file, "save and add another"; posts FormData to the JSON create).
- `admin_annotations.tsx` — the React + MUI annotations editor
  (`app/frontend/apps/annotations`, ported from the Adonis admin; the page
  embeds its payload in `data-payload` and saves via
  `PUT /api/artifact-files/:id/annotations`).

Pages that mount an island set `turbo-visit-control: reload` in `:head` so
Turbo never restores a stale mount from its snapshot cache.

Tailwind v4 notes: dark mode is a `dark` class on `<html>` (applied and
toggled by the `dark-mode` Stimulus controller, which both layouts share —
the admin uses it too), custom classes that other classes `@apply` must be
`@utility`, and the theme lives in `@theme` inside `public.css`.

## Style

Follow the template's rules: small composable functions named after meaning,
transformations over loops, early returns, no boolean parameters, comments
explain why and never what, prefer duplication to the wrong abstraction.
TypeScript is JavaScript with contracts — no type soup. Run `bin/rubocop -a`
before finishing; `rubocop-rails-omakase` is the base.

## Auth

Devise with database_authenticatable, recoverable, rememberable, validatable.
No registration and no OmniAuth — an administrator creates users in the admin,
and the `admin` boolean (via `User#can_administer?`) gates `/admin`. Seeds
bootstrap the admin account from `ADMIN_EMAIL`/`ADMIN_PASSWORD` (required in
production, defaulted in development).

## Deploy

Render via `render.yaml` (Docker). Solid Queue runs inside Puma
(`SOLID_QUEUE_IN_PUMA`); production databases arrive via `DATABASE_URL`.
Active Storage uploads go to S3 — set `AWS_ACCESS_KEY_ID`,
`AWS_SECRET_ACCESS_KEY`, `AWS_REGION`, and `AWS_S3_BUCKET` in Render
(declared `sync: false` in the blueprint). `AWS_S3_KEY_PREFIX` (default
`production`) namespaces blob keys under a folder in the bucket.

## Testing

- `test/models`, `test/services` — domain behavior against the real schema.
- `test/integration` — public pages, the island's API contract, admin gating.
- `test/system` — headless Chrome; guards the Vite/Tailwind/island pipeline.
- `npm run test:frontend` — the island's Vitest suite (ported unchanged;
  happy-dom is pinned to 20.3.1 to match it).

Test behavior, not implementation. Existing tests must keep passing.
